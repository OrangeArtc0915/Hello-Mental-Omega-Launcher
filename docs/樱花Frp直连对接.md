## 2. 为什么卡住（这就是要你们解决的那一段）

### 2.1 三个端口（证据：`client-2022/ClientCore/ProgramConstants.cs:43-46`）

| 端口 | 协议 | 用途 | 隧道是否覆盖 |
|---|---|---|---|
| 1232 | UDP | 局域网大厅发现/聊天（广播） | 否（直连加入不需要） |
| **1233** | **TCP** | **加入游戏的握手**（主机 `TcpListener(Any,1233)`） | **是**，所以大厅能进 |
| **1234** | **UDP** | **进游戏后的对战数据** | **否** ← 问题在这 |

### 2.2 进游戏后，玩家之间靠 `spawn.ini` 互相寻址

写 `spawn.ini` 时，客户端会把**每个其他玩家**的地址写进 `[OtherN]` 段：

```csharp
// client-2022/DXMainClient/DXGUI/Multiplayer/GameLobby/GameLobbyBase.cs:1327-1328
spawnIni.SetStringValue(sectionName, "Ip",   GetIPAddressForPlayer(pInfo));  // 局域网下 = 那条 TCP 连接的对端地址
spawnIni.SetIntValue(sectionName,    "Port", pInfo.Port);                    // LANPlayerInfo.Port = 1234
```

- 局域网大厅里 `GetIPAddressForPlayer` 返回 `LANPlayerInfo.IPAddress`（`GameLobby/LANGameLobby.cs:525-529`），也就是**加入时那条 TCP 连接的对端地址**——刚好就是隧道地址；
- 但端口是 **1234**（`Domain/Multiplayer/LAN/LANPlayerInfo.cs:27-28`）；
- 于是双方 gamemd 都会往 `隧道地址:1234` 发 UDP，而隧道只承载 TCP 1233 → **收不到**。

> ⚠️ **关键约束**：再开一条「UDP 隧道（公网端口 → 本机 1234）」**也不能解决**——樱花FRP 分配的公网端口是随机的（不是 1234），而客户端写死的目标端口就是 1234。所以「游戏内数据」这一段只能由客户端自己承载。

## 3. 需要客户端做的事

### P0 · 让游戏内 UDP 走通（三选一，请你们评估后定）

#### 方案 A · 客户端把游戏 UDP 塞进现有那条 TCP 隧道（改动最小，建议先评估）

思路：

1. 客户端在写 `spawn.ini` 时，把 `[OtherN] Ip/Port` 指向**本机回环的一个中继端口**（例如 `127.0.0.1:xxxx`），而不是隧道地址；
2. 客户端在本地起一个小中继：收到 gamemd 发出的 UDP 包 → 按对端标识打包 → 经**已有的那条 TCP 握手连接**（或新增一条到同一隧道的 TCP 连接）转发出去；
3. 对端客户端解包 → 回注到它本机的 1234；
4. 3 人以上时，房主还要做转发（RA2 是点对点，每对玩家都要通）。

要处理的坑：TCP 上的粘包/边界、UDP 的实时性（丢包/延迟策略）、多对多连接的建立（谁连谁）、房主中转的带宽。

#### 方案 B · 客户端自带穿透

客户端自己起一条 UDP 隧道（或内置 EasyTier/n2n 这类库）。相当于把 HMOL 现在已有的虚拟局域网能力搬进客户端：改动最大，但一劳永逸，也不再依赖樱花FRP。

#### 方案 C · 不动客户端，改用虚拟局域网方案

让玩家在 HMOL 里选 **EasyTier / n2n**（都已内置，客户端一个字不用改，今天就能打）。樱花这条就明确定位成「只能进大厅聊天/看人」。

> HMOL 侧不会再加第二条隧道；上面三条里选哪条、什么时候做，由你们定。

### P1 · 次要项（不急）

| 项 | 说明 |
|---|---|
| 地址框支持域名 | 现在只认 IPv4 字面量（`IPAddress.TryParse`）。HMOL 一律给 IP 形式，所以**可以不做**；将来若想省事可加 `Dns.GetHostAddresses` |
| 记住上次地址 | 锦上添花，HMOL 不做自动写文件 |
| 失败提示 | 隧道没开/地址不对时，聊天区给一句明确原因（现在已有格式错误提示） |

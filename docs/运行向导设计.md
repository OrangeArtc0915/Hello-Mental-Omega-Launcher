# 运行向导（首次运行配置向导）实现说明

> 用途：把这个「首次运行引导」的做法搬到别的程序里。
> 本文只描述**怎么做**与**为什么这么做**，不依赖星露谷启动器本身的业务。
> 实现位置参考：`src/StardewLauncher.App/Windows/ConfigWizardWindow.xaml(.cs)`、`src/StardewLauncher.App/Windows/MainWindow.xaml.cs` 的 `QueueFirstRunWizard()`。

---

## 一、它要解决什么

新用户第一次打开程序时，程序还处于「什么都不知道」的状态：不知道游戏装在哪、依赖装没装、该先点哪个页面。直接把人丢进主界面，用户会先愣住，再自己摸索，最后大概率在某个页面里配错。

向导的职责就是把「第一次必须做对的三件事」按顺序问一遍，**做完即建成可用状态**，用户点一下就能开始用。

三条设计红线：

1. **绝不能打扰老用户。** 判定条件写错一次，就是每次启动都被弹窗骚扰。
2. **绝不能让用户走进死路。** 任何一步都要能跳过、能后退、能手动兜底（自动探测失败时手动选目录）。
3. **绝不替用户做重活。** 向导不做安装、不下载、不改游戏文件。它只做「问」和「记」，重活留给主界面里已经做好的功能。

## 二、触发判定（最关键的一段）

### 判定条件

三个条件**同时**成立才弹：

```
没跑过向导            settings.firstRunCompleted == false
且 一个实例都没有      instances.count == 0
且 设置里没记过目录    settings.gameDir 为空
```

### 「否定即补标记」—— 这是整段逻辑里最容易写错的地方

任一条不成立时，**顺手把 `firstRunCompleted` 置为 true 并落盘**，然后什么都不做。

为什么不这样做会出问题：假设用户是升级上来的老用户，他的 `firstRunCompleted` 字段由于是新增的，值是 `false`。如果不补标记，那么每次启动都要重新判一遍三条——虽然结果都是「不弹」，但语义上永远停留在「可能第一次运行」的状态；更糟的是，只要用户哪天把实例全删了、又把游戏目录清空（比如重置设置），判定突然成立，向导就会在一个用了半年的老用户面前弹出来。

补标记之后，语义变成「这个用户已经过了首次运行的阶段」，之后无论怎么删实例都不会再弹。

### 触发时机

必须在**主窗口完全显示之后**再弹，让出一轮消息循环：

```csharp
Dispatcher.BeginInvoke(DispatcherPriority.ApplicationIdle, () => { ...判定并 ShowDialog()... });
```

原因：窗口内容是在 `OnStartup` 返回之后才建的。在构造函数或 `Loaded` 里直接 `ShowDialog`，向导没有 owner，会跑到屏幕正中、抢焦点，看起来像个野弹窗。等到 `ApplicationIdle` 时主窗口已经画出来了，`Owner = 主窗口` 才生效，居中、模态、焦点全都正常。

### 老用户的手动入口

向导不是一次性的。设置页里留一个「重新运行配置向导」按钮，直接 `new ConfigWizardWindow { Owner = ... }.ShowDialog()`，**不判定任何条件**。这条路径不需要改 `firstRunCompleted`。

## 三、四步流程

每一步的进入动作、可离开条件、以及失败时的兜底：

### 第 1 步 · 欢迎

- **进入动作**：无。
- **可离开**：永远可以（下一步 / 跳过）。
- **内容**：一句话说明程序做什么 + 向导会带你做哪三件事。让用户在 3 秒内知道后面还有几步、大概要花多久。

### 第 2 步 · 选择工作目录

- **进入动作**：**每次都重新探测**一遍候选目录，不要缓存。
  用户很可能在向导开着的时候，切到外面把程序装上了，再切回来。缓存了就要用户重启。
- **内容**：
  - 自动探测出的候选，每行一张可点选的卡片（目录 + 来源说明），左侧圆点表示选中。
  - 一个「手动选择…」按钮兜底（系统目录选择对话框）。
  - 选中后**实时校验**：目录是否真的是目标程序。校验通过才允许下一步。
- **可离开**：`已选中 且 校验通过`。
- **关键点**：校验结果必须**写明失败原因**（「这个目录下没有 xxx.exe，请确认选的是安装根目录」），不能只给一个红叉。用户看不懂原因就只能乱试。
- **关键点**：探测本身抛异常时**不要让向导卡住**，捕获后退化成「候选列表为空，只能手动选」。

### 第 3 步 · 检查依赖

- **进入动作**：读第 2 步校验出来的信息，显示依赖状态。
- **内容**：
  - 依赖已就绪 → 绿色通过，一句话说可以直接下一步。
  - 依赖缺失 → 橙色提醒，**明确说清楚「现在可以先继续，之后去哪里补装」**，并给出替代路径（比如「也可以先建一个不需要它的实例」）。
  - 让用户在这里选择要创建哪一种配置（需要依赖的 / 不需要依赖的）。
- **可离开**：永远可以。依赖缺失**不作为阻止条件**。
- **关键点**：向导里**不实现安装逻辑**。安装是主界面已有的功能，向导里再实现一遍就是两套代码两条路径，以后必然走偏。向导只负责「告诉用户缺什么、去哪装」。

### 第 4 步 · 创建并收尾

- **进入动作**：预填一个合理的默认名字（取目录名，失败时用兜底常量），并显示一张「将要创建什么」的摘要，让用户在落笔前能再核一遍。
- **内容**：名字输入框 + 可选备注 + 最终的创建动作。
- **收尾**：创建成功后 `firstRunCompleted = true` 落盘 → 弹一个「已完成，可以开始用了」的提示 → 关窗。
- **失败处理**：任何异常都 `Log.Error` + 弹错误提示，**不关窗**，用户可以改一改再试。

### 跳过

底部左侧固定放「跳过向导」，**每一步都在、永远可点**。点击后弹一次确认（确认文案里要说清楚「之后可以从哪里再跑一遍」），然后补标记、关窗。

## 四、依赖的能力接口

向导本身不碰磁盘、不碰配置解析。它只调下面四个能力，移植到别的程序时把这四个实现掉即可：

| 能力 | 输入 | 输出 | 说明 |
|---|---|---|---|
| 探测候选目录 | 首选项（可空） | 候选列表，每项含 `目录` + `来源说明` | 至少要覆盖常见安装位置；来源说明是给用户看的（「Steam」「GOG」） |
| 规范化路径 | 原始路径 | 规范化后的绝对路径 | 用户手填的路径要统一处理，避免 `C:\a\` 与 `C:\a` 被当成两个 |
| 校验目录 | 目录 | 成功：安装信息对象；失败：无 | 安装信息里至少要有：可执行文件名、版本号、依赖是否就绪、依赖版本 |
| 创建配置 | 名字、目录、备注、类型 | 创建出的配置对象 | 由被引导方自己实现，向导不关心它存哪里 |

以及一份可读写的设置，只需要一个布尔字段：

```
firstRunCompleted: bool
```

## 五、状态与渲染

### 状态

整个向导只有这几个字段，不要搞成一个大 ViewModel：

```
_step              当前步骤 1..4
_busy              忙状态（创建过程中禁止重复点击）
_selectedDirectory 选中的目录（已规范化）
_selectedInstall   校验结果对象；为 null 表示还没选或校验没过
_kind              要创建的类型
```

「上一步 / 下一步」的可用性**全部**由这几个字段推导，不额外存状态。

### 渲染

四步内容**同处一格**，靠 `Visibility` 切换，不用 `Frame`/页面导航：

```
Step1.Visibility = _step == 1 ? Visible : Collapsed;
Step2.Visibility = _step == 2 ? Visible : Collapsed;
...
```

比页面导航简单得多，也没有历史栈要维护。切步时统一做三件事：切显隐、刷指示点、按这一步的条件设 `下一步.IsEnabled`。

### 步骤指示点

顶部一排「圆点 + 步骤名」，中间用短横线连起来。选中态靠**换资源引用**而不是写死颜色：

```
选中：圆点底色 = 主色，圆点文字 = 反色，步骤名 = 主色 + 半粗
未选：圆点底色 = 边框色，圆点文字 = 次要文字色，步骤名 = 三级文字色
```

这样主题一换整套跟着变，不用手写第二套颜色。

### 候选目录卡片

**不要用 `ListBox`**。整行可点、左侧带选中圆点、每行显示两行文字，自己用 `Border + Grid` 拼更直接，也不用跟 `ListBox` 的默认模板和选中高亮打架。

选中态同样是换资源引用（背景 / 边框 / 圆点三个一起换），配色成对出现：

```
选中：背景 = 主色极淡，边框 = 主色，圆点 = 主色填充
未选：背景 = 卡片色，边框 = 默认边框色，圆点 = 透明填充 + 强边框
```

## 六、坑清单

1. **不要在构造函数或 `Loaded` 里直接弹。** 会没有 owner。用 `Dispatcher.BeginInvoke(DispatcherPriority.ApplicationIdle, ...)`。
2. **不要只判「是不是第一次运行」。** 必须三个条件一起判，并且对老用户补标记。见第二节。
3. **不要缓存候选目录。** 每次进第 2 步重探。
4. **校验失败必须给原因。** 只说「无效」等于没说。
5. **依赖缺失不要拦路。** 只能是提醒 + 给出替代路径。
6. **向导里不要实现安装/下载。** 那是主界面的活。
7. **创建失败不要关窗。** 让用户能改了重试。
8. **写设置时只落布尔标记。** 不要把中间态（选到哪一步了）也存下来——否则用户中途强杀进程，下次启动会从一个半截状态开始，反而更乱。
9. **`ShowDialog` 期间不要动主窗口的页面。** 向导结束、用户点确认之后，主界面该刷新再刷新（本项目的做法是：向导只创建实例，主界面本来就会读一次实例列表，不需要额外通知）。

---

## 七、落地清单

在别的程序里加这个向导，需要动的地方就这些：

| 位置 | 改动 |
|---|---|
| 新建 `ConfigWizardWindow.xaml` + `.xaml.cs` | 四步界面与全部状态逻辑 |
| 主窗口 | 构造末尾调一次 `QueueFirstRunWizard()`；实现里做三条件判定 + 否定补标记 |
| 设置类 | 加一个 `firstRunCompleted: bool`，默认 `false` |
| 设置页 | 加一个「重新运行配置向导」按钮，无条件直接开窗 |
| 文件夹 / 路径常量 | 若向导要展示目录，顺手用上已有的路径常量，不要再拼一份 |

四个能力接口按第四节实现即可，其余一律不动。

## 附：可复用的骨架

```csharp
// ———— 主窗口：触发 ————
private void QueueFirstRunWizard()
    => Dispatcher.BeginInvoke(DispatcherPriority.ApplicationIdle, new Action(() =>
    {
        var s = Settings.Current;

        var needed = !s.FirstRunCompleted && Store.All.Count == 0 && string.IsNullOrWhiteSpace(s.GameDir);

        if (!needed)
        {
            // 老用户：补标记，之后不再白判
            if (!s.FirstRunCompleted) { s.FirstRunCompleted = true; Settings.Save(); }
            return;
        }

        new ConfigWizardWindow { Owner = this }.ShowDialog();
    }));

// ———— 向导：步骤机 ————
private void SwitchStep(int step)
{
    if (step is < 1 or > 4) step = 1;
    _step = step;

    StepWelcome.Visibility   = step == 1 ? Visibility.Visible : Visibility.Collapsed;
    StepDirectory.Visibility = step == 2 ? Visibility.Visible : Visibility.Collapsed;
    StepDependency.Visibility= step == 3 ? Visibility.Visible : Visibility.Collapsed;
    StepCreate.Visibility    = step == 4 ? Visibility.Visible : Visibility.Collapsed;

    Notice.Visibility = Visibility.Collapsed;
    UpdateStepIndicator();

    BtnPrev.Visibility = step == 1 ? Visibility.Collapsed : Visibility.Visible;
    BtnNext.Content = step == 4 ? "完成" : "下一步";

    switch (step)
    {
        case 2: RefreshCandidates(); BtnNext.IsEnabled = false; break;   // 选了并通过校验才放开
        case 3: RefreshDependencyStep(); BtnNext.IsEnabled = _install is not null; break;
        case 4: PrepareSummary(); BtnNext.IsEnabled = _install is not null; break;
        default: BtnNext.IsEnabled = true; break;
    }
}
```

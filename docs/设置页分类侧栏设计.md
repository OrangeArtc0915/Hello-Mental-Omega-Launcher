# 设置页分类侧栏设计（可移植说明）

面向「设置页有很多分类，分类栏直接顶替主侧栏」这一交互。本文只描述模式本身与落点，
不含业务字段，可以直接搬到其它 WPF 程序里用。

## 1. 一句话概括

主侧栏里并排放两组 `StackPanel`：一组是全局导航（`PanNav`），一组是设置分类（`PanelSetupNav`）。
切换页面时只翻转这两个面板的 `Visibility`，**不新建第二个侧栏、不做嵌套布局**。
因此设置页占用的横向空间与其它页面完全一致，返回主页面后主侧栏自动还原。

## 2. 交互约定

| 场景 | 表现 |
| --- | --- |
| 从侧栏点「设置」 | `PanNav` 隐藏、`PanelSetupNav` 显示，默认选中上次停留的分类 |
| 在设置页点某个分类 | 只替换右侧内容卡片，侧栏本身不动 |
| 从设置页跳到别的页 | `PanelSetupNav` 隐藏、`PanNav` 还原，选中态回到被点的那一项 |
| 再回到设置页 | 自动回到**离开前**的那个分类（状态存在窗口里） |

## 3. 文件与职责

以本项目为例（路径可直接对照源码）：

| 文件 | 职责 |
| --- | --- |
| `Windows/MainWindow.xaml` | 侧栏里并排放 `PanNav` 与 `PanelSetupNav` |
| `Windows/MainWindow.xaml.cs` | 页面切换时翻转两个面板；管分类选中态与防回环 |
| `Pages/PageSetup.xaml` | 七张分类卡片同处一格，默认只显示第一张 |

## 4. XAML 骨架

侧栏容器本身是个 `Border`，里面是 `Grid`，两组面板直接并排（同一格，靠显隐互斥，不占两列）：

```xml
<Border Grid.Column="0" Background="{DynamicResource Surface.PanelGlass}">
    <Grid>
        <!-- 全局导航：顺序与显隐由 ApplyNavLayout() 按用户设置排布 -->
        <StackPanel x:Name="PanNav" Margin="0,12,0,0" VerticalAlignment="Top">
            <c:NavItem x:Name="NavSetup" GroupName="MainNav" Tag="5" Text="设置"
                       Icon="lucide/settings" Checked="OnNavChecked" />
            <!-- …其余全局导航项… -->
        </StackPanel>

        <!-- 设置分类栏：进入设置时顶替上面的主导航，离开后还原 -->
        <StackPanel x:Name="PanelSetupNav" Margin="0,12,0,0" VerticalAlignment="Top"
                    Visibility="Collapsed">
            <c:NavItem x:Name="SetupCatAppearance" GroupName="SetupNav" Tag="0"
                       Icon="lucide/palette" Text="外观" Checked="OnSetupCategoryChecked" />
            <!-- …其余分类项，Tag 依次 1..N-1… -->
        </StackPanel>
    </Grid>
</Border>
```

要点：

- 两组面板用**不同的 `GroupName`**（`MainNav` / `SetupNav`）。同名的 `RadioButton` 会互相抢选中，
  而这两组本就应该各自独立记忆选中态。
- 分类项的 `Tag` 就是分类序号，事件处理里靠它把「谁被点了」翻译成索引，不必写一堆 `if`。
- 两组面板放在同一格即可，不需要 `Grid.Row` 切换——显隐互斥已经保证了同一时刻只看到一个。

## 5. C# 切换逻辑

窗口里有两个状态字段：

```csharp
private bool _suppressSetupCategory;   // 程序化改选中态时挡掉 Checked
private int _setupCategory;            // 离开设置页再回来时接着显示哪个分类
```

### 5.1 页面切换时的入口

在 `SwitchToPage(int page)` 里，与「同步导航选中态」并列调用一次：

```csharp
_currentPage = page;
SyncNavSelection(page);
ApplySidebarMode(page);   // ← 新增
```

### 5.2 翻转两个面板

```csharp
/// <summary>
/// 在设置页用分类栏顶替主导航栏，切到别的页面再换回来。
/// 只切两个 StackPanel 自己的 Visibility，主导航项各自的显隐（ApplyNavLayout 设的）不受影响。
/// </summary>
private void ApplySidebarMode(int page)
{
    var inSetup = page == NavPages.Setup;

    PanelSetupNav.Visibility = inSetup ? Visibility.Visible : Visibility.Collapsed;
    PanNav.Visibility = inSetup ? Visibility.Collapsed : Visibility.Visible;

    if (inSetup) SelectSetupCategory(_setupCategory);
}
```

### 5.3 分类选中与防回环

```csharp
private void OnSetupCategoryChecked(object sender, RoutedEventArgs e)
{
    if (_suppressSetupCategory) return;                       // 程序化赋值触发的，忽略
    if (sender is not FrameworkElement { Tag: string tag }) return;
    if (!int.TryParse(tag, out var index)) return;

    SelectSetupCategory(index);
}

/// <summary>切到某个分类：同步侧栏选中态，并让设置页换上对应的卡片。自检走的也是这条路。</summary>
internal void SelectSetupCategory(int index)
{
    if (index is < 0 or > 6) index = 0;
    _setupCategory = index;

    // 程序化改选中态同样会触发 Checked，这里挡掉避免回环
    _suppressSetupCategory = true;
    SetupCatAppearance.IsChecked = index == 0;
    SetupCatBackground.IsChecked = index == 1;
    // …其余分类…
    _suppressSetupCategory = false;

    (GetPage(NavPages.Setup) as PageSetup)?.SwitchCategory(index);
}
```

### 5.4 页面侧：只负责卡片显隐

```csharp
/// <summary>
/// N 张分类卡片同处一格，只把选中的那张显示出来，折叠的卡片不占布局。
/// 侧栏的选中态由 MainWindow 负责，这里只管卡片本身。
/// </summary>
internal void SwitchCategory(int index)
{
    if (index is < 0 or >= CategoryCount) index = 0;

    SurfaceCard[] cards = [CardAppearance, CardBackground, /* … */];

    for (var i = 0; i < cards.Length; i++)
        cards[i].Visibility = i == index ? Visibility.Visible : Visibility.Collapsed;

    ScrollCategory.ScrollToTop();   // 换分类后回到顶部，否则会停在上一个分类的滚动位置
}
```

## 6. 关键坑

1. **`RadioButton` 的 `GroupName` 是全局作用域**，不按可视树分。两组导航必须用不同名字，
   否则在设置页点分类会把主侧栏的选中项也清掉。
2. **程序化改 `IsChecked` 同样会触发 `Checked`**，不挡就会「选中 → 事件 → 再选中」地转圈。
   用一个 `bool` 守卫包住整段赋值即可。
3. **折叠的内容不参与布局**。多张分类卡片叠在同一格、只显示一张，是被支持的用法；
   但任何「量一遍所有分类」的自检必须逐个切出来，见第 8 节。
4. **窗口与页面的生命周期不同**。窗口始终存活，页面可能被缓存复用，所以「当前选的是哪个分类」
   这个状态放在**窗口**里（`_setupCategory`），页面只按指令渲染。
5. **只切面板的 `Visibility`，不要动态增删 `NavItem`**。增删会重新触发选中逻辑，
   而 `Visibility` 切换是无副作用的，也不会影响用户对主导航做的排序/隐藏设置。

## 7. 移植清单

1. 在侧栏容器里新建第二个 `StackPanel`（`PanelSetupNav`），`Visibility="Collapsed"`，
   放设置分类项，`GroupName` 与主导航不同，每项 `Tag` 填分类序号。
2. 给分类项挂同一个 `Checked` 事件。
3. 在页面切换的统一入口（本项目是 `SwitchToPage`）调用 `ApplySidebarMode(page)`。
4. 在窗口里加 `_setupCategory` / `_suppressSetupCategory` 两个字段与 `SelectSetupCategory(int)`。
5. 在设置页里把分类卡片叠进同一格，实现 `SwitchCategory(int)` 做显隐。
6. 用 `NavPages.Setup` 之类的常量判断「当前是不是设置页」，不要散落魔法数字。

## 8. 自检钩子（可选）

本项目有一套页面自检：逐宽度、逐页面、逐子视图跑重叠检测。
分类卡片是折叠的，所以要能把每个分类单独切出来量一遍。约定放在页面基类上：

```csharp
// LauncherPage
public virtual int SubViewCount => 1;
public virtual void SelectSubView(int index) { }

// PageSetup：分类栏挂在窗口主侧栏上，自检也走窗口那条路，保证和真实点击一致
public override int SubViewCount => CategoryCount;
public override void SelectSubView(int index)
    => (Window.GetWindow(this) as MainWindow)?.SelectSetupCategory(index);
```

让自检走 `SelectSetupCategory`（而不是直接调 `SwitchCategory`）的好处：选中态、侧栏切换、
卡片显隐三件事都被覆盖到，测的就是用户真实点一下走的那条路。

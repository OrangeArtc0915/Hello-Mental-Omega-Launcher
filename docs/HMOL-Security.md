## 安全特性

### 1. 凭据保护

| 措施       | 说明                                |
| -------- | --------------------------------- |
| **加密存储** | API 密钥、令牌、群组 ID 使用 AES-256-GCM 加密 |
| **机器绑定** | 密钥基于机器指纹派生,跨机器不可移植                |
| **环境变量** | 支持 环境变量注入                         |
| **外部配置** | 支持 (不提交到 git)                     |
| **优先级链** | 环境变量 > 外部配置 > 加密 seal 模块          |

### 2. 代码保护

| 措施                    | 说明                 |
| --------------------- | ------------------ |
| **PyInstaller --key** | 发布 EXE 时 AES 加密字节码 |
| **反调试**               | 检测调试器附加            |
| **反虚拟机**              | 检测常见 VM 特征         |
| **完整性校验**             | 关键模块 SHA-256 哈希校验  |
| **审计日志**              | 所有凭据访问、解密操作都有日志    |

### 3. 通信安全

| 协议        | 实现                |
| --------- | ----------------- |
| HTTPS     | 所有外部 API 调用强制 TLS |
| OAuth 2.0 | 微软账号登录(MSAL)      |
| 设备代码流     | 无需本地 HTTP 服务器     |

## 加密算法

| 算法                       | 用途       | 标准              | 备注          |
| ------------------------ | -------- | --------------- | ----------- |
| **AES-256-GCM**          | 对称加密(认证) | NIST SP 800-38D | 加密令牌、敏感数据   |
| **PBKDF2-HMAC-SHA256**   | 密钥派生     | NIST SP 800-132 | 200,000 轮迭代 |
| **HKDF-SHA256**          | 子密钥派生    | RFC 5869        | 从主密钥派生子密钥   |
| **RSA-2048-OAEP-SHA256** | 非对称加密    | RFC 8017        | 备用(密钥交换)    |
| **HMAC-SHA256**          | 完整性校验    | RFC 2104        | 防止篡改        |
| **SHA-256**              | 哈希       | FIPS 180-4      | 完整性校验       |

## 运行时保护

### 1. 反调试

### 启动器会:

- 检测 `IsDebuggerPresent()` / `CheckRemoteDebuggerPresent()`
- 检测常见调试器进程(x64dbg、ollydbg、idaq)
- 异常时弹出警告 + 写入审计日志

### 2. 反虚拟机

检测 VM 特征:

- 已知 VM 厂商的 MAC 地址前缀(00:05:69、00:0C:29 等)
- VM 工具进程
- 注册表 VM 特征

> 注意: 反 VM 仅作**审计记录**,不会强制退出(避免影响合法用户)。

## 报告漏洞

> 🔒 **请勿在公开 Issue 中报告安全漏洞!**

### 报告方式

通过 GitHub **私有漏洞报告**:
<https://github.com/OrangeArtc0915/Hello-Mental-Omega-Launcher/security/advisories/new>

### 响应 SLA

| 阶段   | 时间              |
| ---- | --------------- |
| 确认收到 | 48 小时内          |
| 初步评估 | 7 天内            |
| 修复计划 | 14 天内(复杂漏洞可能延长) |
| 公开披露 | 修复发布后 90 天      |

### 报告应包含

1. **漏洞类型**: CWE 编号(可选)
2. **影响范围**: 受影响的版本
3. **复现步骤**: 详细步骤
4. **概念验证 (PoC)**: 代码/截图
5. **影响评估**: CVSS 评分(可选)
6. **已知缓解**: 是否已有 workaround

### 致谢

经本人同意,安全研究者将在 [SECURITY.md](../SECURITY.md) 中致谢。

## 最佳实践

### 用户

1. **不要**分享你的 `HMOL_secrets.json` 或环境变量
2. **不要**在公开场合发布 HMOL 配套的熵文件
3. **定期**运行 `python HMOL_seal_secrets.py --rotate` 轮换密钥
4. **使用** 防病毒软件保护本地凭据
5. **不要**从非官方渠道下载 HMOL(可能包含恶意修改)
6. **不要**禁用 Windows SmartScreen 后运行 HMOL

### 审计人员(安全研究)

1. **绝不**提交任何修改后的代码到 PR
2. **遵循** [OWASP Python Security](https://owasp.org/www-project-python-security/) 指南
3. **理解** 本项目不接受代码修改类的 PR,但欢迎通过 Security Advisories 报告问题

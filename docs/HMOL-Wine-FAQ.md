## 🛠️ 安装与启动

### Q1. 双击 EXE 没有反应？

**可能原因**：

1. 杀软拦截（误判）
2. VC++ 运行库缺失
3. 启动器在 `C:\Program Files` 等受保护目录
4. 残留进程占用

**解决方法**：

1. 任务管理器 → 结束所有 `HMOL.exe` 进程
2. 重新启动尝试
3. 若仍无效，将启动器移到 `D:\HMOL\` 等可写目录
4. 安装 [VC++ 2015-2022 Redistributable (x64)](https://aka.ms/vs/17/release/vc_redist.x64.exe)
5. 将启动器目录加入杀软白名单

### Q2. EXE 报毒被杀软删除？

**A**：HMOL 包含加密模块、`subprocess` 调用，少数杀软会启发式误报。**HMOL 源码完全公开**，可自查。

**解决**：

1. **将启动器目录加入信任区**（不要全局关闭杀软）
2. 通过 SHA-256 校验 EXE 是否与 GitHub Release 一致
3. 若不放心，可在 [VirusTotal](https://www.virustotal.com/) 上传哈希查询多引擎结果

### Q3. 必须用管理员运行吗？

**A**：**必需**。管理员权限可避免：

- 写入 `Program Files` 失败
- 杀软误拦
- 系统目录权限问题

**但**：放入 `D:\HMOL\` 等用户可写目录，普通权限即可。

### Q4. 可以放在 U 盘/移动硬盘上运行吗？

**A**：**可以**。但需注意：

- U 盘格式化为 NTFS（FAT32 不支持 4GB+ 文件）
- 路径中避免中文（推荐 `E:\HMOL\`）
- 弹出 U 盘前先关闭启动器

## 🎮 实例与游戏

### Q7. 提示"指定路径不是有效的心灵终结游戏目录"？

**A**：所选目录缺少 `Mental_Omega_client.exe`。请确认：

- 选择的是**游戏根目录**（含 `Mental_Omega_client.exe`）
- 不是 `Saves/`、`Maps/` 等子目录
- 不是快捷方式所在目录

### Q8. 启动游戏后没反应？

**可能原因**：

1. 杀软拦截 `Mental_Omega_client.exe`
2. 缺少 VC++ 运行库
3. 游戏目录权限不足
4. 显卡驱动问题

**排查**：

1. 直接双击游戏目录下的 `Mental_Omega_client.exe` → 是否能启动？
2. 若能 → 启动器问题，加入白名单
3. 若不能 → 系统/游戏问题

### Q9. 启动器会改动游戏文件吗？

**A**：**会**。但**只在以下情况**：

- 主动安装插件包时（写入 `Maps/`、`INI/` 等）
- 主动备份/还原时
- 主动卸载插件包时（按记录删除）

**不会**：

- 启动游戏时（只 `Popen` 主程序）
- 浏览资源时（只读 `os.scandir`）
- 后台运行时

### Q10. 同一台机器能装多版本心灵终结吗？

**A**：**可以**。将不同版本安装到不同目录（如 `D:\MO_336\`、`D:\MO_私人版`），在启动器中分别添加为实例。

**注意**：每个游戏目录只能绑定一个实例，不能两个实例共用同一目录。

### Q11. 删除实例会删除游戏吗？

**A**：默认**不会**！删除实例时弹出确认：

```
[ ] 同时删除游戏文件 (不可恢复!)
```

取消勾选 = 仅删除启动器中的注册信息，游戏文件保留。
勾选 = 同时删除游戏文件（**不可恢复**）。

> ⚠️ 建议删除前先 [备份](HMOL-Wine-Features#备份与还原)。

## 📦 插件包

### Q12. 包支持哪些格式？

| 格式     | 支持 |
| ------ | -- |
| `.zip` | ✅  |
| `.7z`  | ✅  |
| `.rar` | ✅  |
| `.map` | ✅  |

### Q13. 安装包时提示"文件冲突"怎么办？

**A**：新包与已安装的包存在文件重叠。三种选择：

1. **覆盖**：新包内容替换旧内容
2. **取消**：保留旧包
3. **先卸载旧包**：再装新包

### Q14. 卸载包会删错其他包的文件吗？

**A**：**不会**。HMOL 使用 `install_record.json` 精确记录每个包安装的每个文件，卸载时只删除记录中的文件。

### Q15. RAR 包解压失败？

**A**：

1. 安装 [WinRAR](https://www.win-rar.com/)（自带 `unrar.exe`）
2. 或将 `unrar.exe` 放入 PATH
3. 或改用 ZIP/7Z 格式的版本

## 🔐 登录与 OneDrive

### Q16. 微软登录失败？

**常见原因**：

- 网络无法访问 `login.microsoftonline.com`
- 系统时间偏差过大（> 5 分钟）
- 防火墙拦截

**排查**：

1. 浏览器打开 <https://microsoft.com/devicelogin> → 是否能访问？
2. 同步 Windows 时间
3. 关闭代理/VPN 后重试

### Q17. 微软登录后多久会过期？

**A**：

- access\_token：\~1 小时
- refresh\_token：\~90 天（使用即续期）
- HMOL 在 token 即将过期时自动刷新，无需手动操作

### Q18. OneDrive 看不到文件？

**可能原因**：

1. 分享链接已失效
2. 链接未设为"任何人可查看"
3. 链接是个人 OneDrive 而非 SharePoint

**解决**：

1. 重新生成公开共享链接
2. 确认是 SharePoint 链接

### Q19. 退出登录后还能用吗？

**A**：可以。退出登录仅清除本地加密令牌，不影响其他功能（实例、插件包、备份等仍可使用）。仅 OneDrive 浏览和微软账号相关功能不可用。

## 📢 QQ 喊话

### Q20. 喊话发送失败？

**常见错误**：

| 错误            | 解决                 |
| ------------- | ------------------ |
| `未登录`         | 先完成微软账号登录          |
| `Token 获取失败`  | 检查 AppID/AppSecret |
| `频道:err(403)` | 机器人被移出频道或无发言权限     |
| `群:err(403)`  | 机器人被移出群或被禁言        |
| `操作过于频繁`      | 等待 5 分钟（5 次/分钟 限制） |

### Q21. 为什么不允许发 URL？

**A**：QQ 平台**严格禁止机器人消息包含 URL**，触发后机器人会被封禁。HMOL 在客户端先做检测，避免被封。

### Q22. 喊话字数限制？

| 字段      | 上限    |
| ------- | ----- |
| MO 版本   | 10 字  |
| 房间名     | 15 字  |
| 房间密码    | 10 字  |
| **总字数** | 500 字 |

### Q23. 5 分钟内最多喊几次？

**A**：5 次 / 分钟。触发后需等待 N 秒才能再次发送。

## 🔒 安全与许可

### Q24. 启动器会上传我的数据吗？

**A**：**不会**。

- 无中央服务器
- 无遥测
- 无第三方分析 SDK

**仅在用户主动操作时联网**：

- 微软设备代码流
- OneDrive 资源下载
- QQ 喊话
- （可选）版本检查

### Q25. 令牌会被盗吗？

**A**：HMOL 做了多重保护：

- **AES-256-GCM 加密**存储到本地
- **机器指纹绑定**：跨机器无法解密
- **进程隔离**：解密只在内存中，进程退出后清除

### Q26. 为什么不能修改源码？

**A**：HMOL 使用「禁止二次修改许可证 v2.2」，目的是：

- 防止恶意篡改后冒名发布
- 保护 HMOL 品牌完整性
- 便于追踪唯一官方版本

**许可证允许**：

- ✅ 阅读、学习、研究
- ✅ 提交 Bug 报告
- ✅ 个人非商业使用

**不允许**：

- ❌ 任何修改、二次开发、二次封装
- ❌ Fork 修改后重新分发
- ❌ 商业使用

详见 [Security and License](HMOL-Wine-Security-and-License)

### Q27. 我能改启动器图标/名称吗？

**A**：**不能**。这属于 §3.9「标识移除」条款。

### Q28. 反馈 Bug 后多久会处理？

**A**：

- 确认收到：48 小时内
- 初步评估：7 天内
- 修复发布：随下个版本（无 SLA 保证）

## 🔧 错误排查

### Q31. 弹窗错误信息看不懂？

**A**：查看 [Error Codes](HMOL-Wine-Error-Codes) 手册的对应章节。149+ 条错误码均含可能原因 + 解决方法。

或使用命令打开本地手册：

```
docs/HMOL_错误代码与解决方法.docx
```

### Q32. 启动器日志在哪里？

**A**：`启动器目录/logs/HMOL_<日期>.log`

例如：`D:\HMOL\logs\HMOL_2026-07-20.log`

反馈 Bug 时请附上当天的日志文件。

### Q33. 怎么彻底重置启动器？

```powershell
# 1. 关闭启动器
# 2. 删除以下文件/目录（在启动器根目录下）
del HMOL_config.json
del msal_cache.bin
rmdir /s /q instances
rmdir /s /q backups
rmdir /s /q temp
rmdir /s /q logs

# 3. 重新启动
HMOL.exe
```

> ⚠️ 这会删除所有实例、备份、令牌。**操作前请手动备份** **`HMOL_config.json`**。

### Q34. 启动器自动退出？

**可能原因**：

1. **EULA 拒绝**：第一次启动点「不同意」 → 自动清理退出
2. **反调试触发**：调试器附加时主动退出
3. **VM 检测**：常见虚拟机中主动退出
4. **完整性校验失败**：关键模块被篡改

正常个人 PC 桌面不会触发后三种。**详细原因见** **`logs/audit_help.log`**。

### Q35. 启动器占 CPU 很高？

**A**：可能原因：

1. 一次性导入大量资源
2. 后台轮询 OneDrive
3. 搜索大型实例目录

**临时解决**：等待任务完成。如持续高 CPU，请提交 Issue 并附日志。

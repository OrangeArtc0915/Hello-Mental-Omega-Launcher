【这个包修什么】
 · 局域网大厅：解锁「队伍 A/B/C/D」选择
 · 局域网：修加入者开战后崩溃（spawn.ini 队伍索引越界）
 · 局域网：修 "The client is already connected!" 崩溃
 · 局域网：补齐「加入时裁掉超过 8 人的 AI」
 · 局域网大厅底部新增「地址输入框」—— 粘 IP:端口 回车直连（给樱花 Frp 用）
 · 樱花 Frp：新增「游戏内 UDP 中继」，让只开一条 TCP 隧道也能真正开打
 · 局域网：修「退出大厅重新建房后，收到残留连接发来的旧消息就崩溃」
   （KABOOOOOOOM → 调用的目标发生了异常。 → 未将对象引用设置到对象的实例。）
   这是上游 CnCNet 局域网大厅本来就有的漏判空（在线大厅同一处有判空，只有局域网漏了），
   原版客户端也会崩，本补丁补上了这个判断。
 · 局域网：修「客机断线重连/退出后，房主收到那条已断开的连接发来的包就崩溃」
   （KABOOOOOOOM → 调用的目标发生了异常。 → **无法访问已释放的对象。对象名:"System.Net.Sockets.Socket"**）
   上游在"不认识的局域网命令"那句日志里会用 `lpInfo.ToString()` 读 `RemoteEndPoint`，
   连接已释放就抛异常，直接把客户端打崩。本补丁在入口处先判断连接是否已废，废了就丢掉这条消息；
   同时补丁自己的控制帧不再落到客户端的"未知命令"分支（以前会让两边日志每秒刷上百行）。
 · 局域网：让「踢人」真正生效
   （玩家名字下拉框里选「踢出」以前"点了没反应" —— 在线大厅重写了 KickPlayer，
     局域网大厅用的是基类空实现。本补丁补上了局域网的实现：房主点踢出后，
     该玩家会被断开并退回局域网大厅，其余人界面上的玩家列表会自动更新。）
 · 局域网：@ 功能 + 名字补全
   · 聊天里写「@某人」（如 @mmm），被 @ 的人会看到那条消息变成**青色**，
     并且正文最前面出现一个「[@你]」标记，同时听到**提示音**。
     （提示音是补丁自己生成的"叮—咚"，不用客户端音效、不看系统声音方案，没有版权问题。）
   · 输入「@」+ 名字的前几个字母，按 **Tab** 自动补全成完整玩家名。
     例：输入「@mm」按 Tab → 「@mmm」。
     只在聊天输入框处于选中状态时才响应，不会影响别的控件用 Tab。
     匹配不到会写进 MoLanRelay.log（"@补全：没有匹配 ..."）。
   · 另外两种 @：
     `@所有人` / `@all`  —— 房间里所有人都高亮 + 提示音；
     `@队伍N` / `@teamN` —— 只提醒队伍编号是 N 的人（N 就是游戏里显示的 1~4）。
   · 按 **F9** 可以开/关 @ 提示音（大厅聊天区会提示当前状态）。
 · 主菜单：隐藏「CnCNet 线上大厅」入口，下面的按钮整体上移 42 像素
   （本补丁只做局域网联机，线上大厅留着容易点错）

   直接覆盖版不改 ini，由中继在客户端启动后自动隐藏（第三方主题不会被覆盖）。
   想恢复入口只能还原 exe（运行「还原.bat」），只把 ini 改回去是不够的。
 · 顶部栏：关闭「CnCNet 大厅 (F3)」「私信 (F4)」「注销」三个按钮，状态文字改成「局域网大厅」
   （F3/F4 热键一并失效；F2 回主菜单仍然可用）
 · 设置窗口：「CnCNet」「更新」两个标签页和右上角「下载音乐包」按钮已删除；
   新增一个「联机补丁」页，里面 10 个开关（保存在 Resources\MoLanPatch.ini，改动即生效）：
       @ 提示音（F9 也可切换）

       有人掉线时在聊天区提示
       进房间自动报一次版本

 1. 先把客户端和游戏完全关掉（任务管理器确认 clientdx.exe 已消失）。
 2. 把本压缩包解压到任意位置。

      <游戏根目录>\_MO补丁备份\

================================================================
 一、为什么需要「游戏内 UDP 中继」
================================================================

原版局域网：大厅靠 UDP 广播发现，加入靠 TCP 1233 握手，
**进游戏后靠 UDP 1234 点对点互发数据**。
樱花 Frp 只把 TCP 1233 映射出来，所以：
    能进大厅、能看到玩家列表，但**一点开始就卡在同步／不读条**。

本补丁把 gamemd 发出的 UDP 包**封进大厅已有的那条 TCP 连接**里转发（不新增隧道、
不新增端口），对端解包后再注入它本机的 gamemd：

    gamemd ─UDP→ 127.0.0.1:1234x ─┐
                                 │ 封成 MO-RELAY 帧
    大厅聊天/选项 ────────────────┴─→【同一条 TCP 连接】─→ 隧道(1233) ─→ 房主
                                                                        │
                       房主按目标分发（2 人直接转发；3 人以上经房主中转）
                                                                        ↓
    对端中继 ─解帧→ 从 1234x 注入 ─UDP→ 对端 gamemd:1234

安装后无需任何设置，开打时自动生效。
**参与联机的每一台机器都必须装过本补丁，且版本号要一致。**


【怎么确认它在工作】
 游戏根目录会生成 `MoLanRelay.log`，正常应该看到：

    ======== MoLanRelay v0.6.0 ========      ← 几台机器这一行必须一模一样
    载入的 DLL: D:\...\Resources\MoLanRelay.dll
    register host client: connected / 127.0.0.1:xxxxx
    start: self=<你的名字> host=True/False (byOrder=.. byConn=..) 玩家数=N 本机端口表=[名字→端口]
    peer[1] <对端名字> listening 127.0.0.1:12341
    stats: 本机游戏发出的包=.. 已注入本机游戏=.. 已发出帧=.. 已转发帧=.. 已收到帧=.. | 分对端: 名字(收X/注Y)

 判断标准：两边的 `已发出帧` 和 `已收到帧` 都持续上涨（差距在个别包以内）= 通了。
 出问题时把这个日志发出来即可定位。

 ⚠️ 排错第一步永远是看第一行版本号：只要有一台是旧版，就会莫名其妙地
    「它发的帧对面收不到」，直接表现为不读条。版本不一致就重新装一遍本包
    （两个 MoLanRelay.dll 位置都要换）。

 ⚠️ 已知代价：这是**用 TCP 承载 UDP**，网络抖动时**可能卡顿**（TCP 有队头阻塞，
    而 RA2 锁步对延迟敏感）。这是方案固有代价，不是 bug。
    **想要手感最好，请用虚拟局域网方案（EasyTier / n2n）** —— 那是 UDP 承载，本补丁不参与。


================================================================
 二、局域网大厅新增的「直连」输入框
================================================================

【界面在哪】
 进局域网大厅后，看窗口**底部那一排**，靠右（「返回主菜单」左边）多了一个输入框：

     [创建房间] [加入游戏]  ......  [ 输入 地址:端口 后回车直连 ]  ...  [返回主菜单]

【怎么用】
   1. 点一下输入框
   2. 填 地址:端口（樱花 Frp 复制出来的 IP:端口 直接 Ctrl+V 粘贴即可）
   3. 按回车 → 立刻尝试连过去

   容错：支持 Ctrl+V 粘贴；中文冒号「：」也能认；粘贴内容带前后缀
        （如 "服务器: 1.2.3.4:1234"）也能认出地址；只填 IP 不填端口 → 默认 1233；
        地址不合法 → 聊天区提示格式并清空输入框；只支持 IPv4 字面量，不支持域名。

 三、怎么还原
================================================================

 双击包里的「还原.bat」即可：它会把 <游戏根目录>\_MO补丁备份\ 里的原文件覆盖回去，
 并删掉本补丁新增的那两个 MoLanRelay.dll。

 也可以手动还原：
   _MO补丁备份\Resources\...  →  游戏根目录\Resources\...
 再顺手删掉 Resources\MoLanRelay.dll 与 Resources\Binaries\MoLanRelay.dll 即可。


================================================================
 四、开赛前的 3 秒检查（HMOL）
================================================================

 用 HMOL 启动游戏时，HMOL 会把「自己的版本 + 这个实例装了哪些包」写进
 Resources\HMOL.session.txt。局域网大厅里房主点「开始游戏」后：

   1. 房主先不开始，向所有已连接的对端要一份同样的信息；
   2. 等 3 秒（只等一次，客机不额外等待）；
   3. 房主把双方数据对比一遍，结果显示在自己和所有人的聊天区：
      · 一致   → 绿字「检查通过：双方 HMOL 版本与已安装包一致（已核对 N 人）」，直接开始
      · 不一致 → 红字列出差在哪（HMOL 版本不同 / 谁缺哪个包 / 谁不是从 HMOL 启动），
                 同时弹出一个「是 / 否」确认框，**先停住，不会开始**
      · 没法核对（没从 HMOL 启动）→ 红字提示「未检测到 HMOL 会话信息」，
                 同样弹「是 / 否」确认框，**先停住，不会开始**
   4. 确认框：
      · 框里只有一句短话（客户端消息框只有一行、宽度固定，写长了会被切掉）：
        「检查到 N 项不一致，详见聊天区。仍然开始?」
      · 具体哪个人、哪个包不一样，**完整列表在聊天区那条红字里**（能换行、能往上翻）
      · 点「是」→ 继续开始游戏
      · 点「否」→ 停止开始，留在局域网大厅（差异已经在聊天区列出来了），
        **并自动解锁房间** —— 因为开局要求先锁定房间，不解锁的话朋友会「刚进去就自动退」
        （客户端日志里是 `Dropping client because the game room is locked.`）
        把版本 / 已安装包对齐后重新点「开始游戏」即可（记得再锁一次房间）

 注意：
   · 只比对**包名**（HMOL 目前没有包的版本号字段），不比文件哈希。
   · 房主只有一个人（没有其他玩家）时没有可比对象，直接开始，不会等 3 秒。
   · 客机没装本补丁 → 房主收不到回信，会提示「没收到 X 的检查信息」；
     3 秒内没收到会自动补问一次（再多等 2 秒），避免一次丢包就误报。
   · **更新补丁时必须把 `Resources` 里的 3 个 exe 和 `MoLanRelay.dll` 一起换。**
     只换 DLL 的话，旧 exe 里没有 MO-CTRL 识别代码，检查请求根本不会被处理，
     表现就是「对方一直提示没收到检查信息」，而且旧 exe 还会因为残留连接崩溃。
   · 等待期间如果退出/隐藏大厅，这一轮检查会自动取消，回大厅后不会自己开局，
     重新点一次「开始游戏」即可。
   · 直接从客户端 exe 启动（不是从 HMOL 启动）时没有 session 文件，没法核对：
     房主点开始后同样会**停下并弹确认框**（提示「未检测到 HMOL 会话信息」），
     选「是」照常开始，选「否」停在局域网大厅。


================================================================
 五、注意事项
================================================================
· gamemd.exe / Syringe.exe 仍保留「以管理员身份运行」（原安装自带），
  开打时可能弹一次 UAC，点「是」即可。

· 中途任何一步失败，脚本会自动回滚到打补丁之前的样子。
· 如果客户端自带的更新器之后把 Resources 里的文件重新下载覆盖了，
  重新运行一次「安装.bat」即可。
· 本包**不含**中文输入修复，那部分在「补丁 1／中文输入」里，两个包互不冲突。

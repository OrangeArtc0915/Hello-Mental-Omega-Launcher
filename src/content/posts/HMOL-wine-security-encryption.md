# HMOL wine版 安全加密方案

## 设计原则

HMOL wine版需要安全存储以下敏感数据：

- 微软账号的 OAuth access_token 和 refresh_token
- QQ 开放平台 Bot Token
- 用户自定义配置中的敏感字段

为此，我们设计了一套**机器绑定 + 多层加密**的存储方案，确保即便配置文件被拷贝到其他机器，也无法解密其中的敏感数据。

## 加密架构

### AES-256-GCM

所有敏感数据均使用 **AES-256-GCM** 算法加密：

- **AES-256**：256 位密钥，当前计算能力下无法暴力破解
- **GCM 模式**：同时提供加密和完整性校验，防止密文被篡改
- **随机 IV**：每次加密生成 12 字节随机初始化向量，确保相同明文产生不同密文

### 密钥派生

密钥通过以下流程派生，确保与当前机器硬件绑定：

```
用户首次启动
  ↓
收集机器指纹 (CPU ID + 主板序列号 + 系统安装时间等)
  ↓
PBKDF2-HMAC-SHA256 (100,000 次迭代) + 随机盐
  ↓
256-bit 主密钥
  ↓
AES-256-GCM 加密用户凭据
  ↓
密文 + IV + Tag 存储到 HMOL_config.json
```

### 机器绑定

核心安全特性：**加密密钥依赖于当前机器的硬件指纹**。

- 如果配置文件被复制到另一台机器 → 密钥派生结果不同 → **解密失败**
- 如果硬件发生重大变更（如更换主板）→ 需重新输入凭据
- 启动器首次运行时会自动完成密钥初始化，用户无需手动操作

## 安全审计

### 启动时自检

启动器启动时执行以下安全检查：

1. 验证加密熵文件 `HMOL_crypto_entropy.bin` 完整性
2. 检查配置文件签名是否被篡改
3. 验证 EULA 接受记录的完整性
4. 检查运行时内存中的密钥是否被意外泄露到日志

### 安全日志

所有安全相关事件（解密失败、签名不匹配、配置文件异常等）会记录到独立的安全日志，方便排查问题。

## 威胁模型

| 威胁场景 | 防护措施 |
|----------|----------|
| 配置文件泄露 | 机器绑定，其他设备无法解密 |
| 中间人攻击 | 所有外部通信强制 HTTPS + TLS 1.2+ |
| SSRF 攻击 | 禁止访问内网地址（10/8、172.16/12、192.168/16） |
| 内存转储攻击 | 密钥仅在需要时解密到内存，使用后立即清除 |
| 配置文件篡改 | 签名校验，篡改后启动器拒绝加载 |

## 用户最佳实践

1. **不要手动编辑 `HMOL_config.json`**：任何手动修改都可能导致签名不匹配，启动器将拒绝启动
2. **定期备份配置文件**：建议将整个启动器目录纳入你的常规备份计划
3. **更换硬件前撤销敏感凭据**：如果计划更换主板或重装系统，先在设置中清除存储的凭据

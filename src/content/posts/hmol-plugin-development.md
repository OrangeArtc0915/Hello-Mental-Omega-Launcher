# HMOL 扩展模块开发指南

> [!IMPORTANT]
> 本文对应**当前版本**：C# / .NET 8 版 `v1.0.0`。
> 扩展是**纯声明式**的：启动器不加载任何插件程序集、不执行扩展提供的代码。想做主页小组件，请按下文的**声明式扩展**来写。

## 一、扩展是什么

一个扩展就是**一份 JSON 清单**。放进扩展目录后，它会像内置的「日历 / 天气 / 常用网站」那样，在主页小组件区显示成一张同款卡片。

```
<数据目录>\extensions\我的小组件.json
```

> [!WARNING]
> **安全边界（先看这段）**
>
> - 扩展是**纯声明式配置，不会被「执行」**：启动器不加载任何程序集、不引入脚本引擎（没有 Roslyn、没有 Lua / JS），扩展里也没有任何可写代码的字段；
> - 启动器**不会读写你电脑上的文件**、不改注册表、不启动任何进程 —— 只有「读写扩展目录里的清单本身」这一件事；
> - 数据源只做 **http / https 的只读 GET**，有超时、失败自动降级、结果只缓存在内存里（不落盘），还可以在设置里一键关掉；
> - 不存在的图标、写坏的字段、非法网址，都只会让**这一个**扩展被跳过并给出中文原因，不影响启动器与其它扩展。

## 二、放在哪、怎么生效

| | |
|---|---|
| 扩展目录 | `<数据目录>\extensions\`（设置 → 扩展模块 → 卡片上的「扩展目录」就是它的绝对路径） |
| 数据目录 | 默认是 `启动器目录\Data`，可用环境变量 `HMOL_DATA` 重定向 |
| 一个文件 = 一个扩展 | 目录下的每个 `.json` 文件就是一个扩展，**文件名（去掉 `.json`）就是它的 ID** |
| 以 `.` 开头的文件 | 会被忽略（留着放宿主自己的元数据） |
| 子目录 | 会被忽略（扩展只认目录根部的 `.json` 文件） |

生效方式有两种，效果一样：

1. 设置 → 扩展模块 → 点 **重新加载**（推荐，能立刻看到校验结果）；
2. 回到主页（每次进入主页都会重新读一遍扩展目录）。

想改就直接改清单文件；想停用就在设置页点一下电源按钮（会把 `enabled` 改成 `false`），或者干脆把文件删掉。

## 三、字段表

字段名大小写不敏感（`title` 与 `Title` 等价），允许写 `//` 注释与结尾多余逗号。**没写的字段就是不显示**，除了 `title` 之外没有必填项。

| 字段 | 类型 | 默认 | 上限 / 取值 | 说明 |
|---|---|---|---|---|
| `title` | string | — | **必填**，≤ 40 字 | 卡片标题 |
| `version` | string | 空 | ≤ 20 字 | 版本号，只用于展示 |
| `author` | string | 空 | ≤ 30 字 | 作者，显示在卡片右上角与设置页列表 |
| `description` | string | 空 | ≤ 120 字 | 一句话说明，只显示在设置页列表里 |
| `icon` | string | `puzzle` | ≤ 40 字，且必须是内置图标名 | 卡片图标，可写 `coffee` 或 `lucide/coffee`；名字不存在会被判为清单无效 |
| `value` | string | 空 | ≤ 60 字 | 主数值（卡片上的大字）。配了数据源时它是「取不到数据」时的降级显示 |
| `lines` | 数组 | 空 | ≤ 8 项 | 文字行，每项 `{ "label": "标签", "text": "内容" }`，`label` 可省略（省略就只显示 `text`） |
| `lines[].label` | string | 空 | ≤ 12 字 | 行标签，显示成「标签：内容」 |
| `lines[].text` | string | 空 | ≤ 200 字 | 行内容 |
| `dataSource` | 对象 | 无 | — | 可选的数据源；给了它才会联网 |
| `dataSource.url` | string | — | ≤ 500 字，必须是 http/https | 要 GET 的网址 |
| `dataSource.path` | string | 空 | ≤ 200 字 | 从返回的 JSON 里取哪个值 |
| `dataSource.refreshSeconds` | int | `600` | 60 ~ 86400 | 刷新间隔（秒），同时也是缓存有效期 |
| `link` | string | 空 | ≤ 500 字，必须是 http/https | 填了之后**整张卡可点**，用系统默认浏览器打开 |
| `enabled` | bool | `true` | — | 是否启用；停用后主页不显示，清单仍然保留 |

两条额外的校验规则：

- `value`、`lines`、`dataSource` **至少要有一项**，否则卡片上什么都不会有；
- 网址除了协议之外还要求主机名像样（和「常用网站」同一套规则）：`https://notaurl` 这种会被拒绝。

## 四、一个完整示例

仓库里有一份可以直接用的模板：`docs/extensions/示例.json`。把它复制到扩展目录就有一个「示例天气」卡片。

```json
{
  "title": "示例天气",
  "version": "1.0.0",
  "author": "HMOL",
  "description": "示例扩展：只读 GET 一个公开接口（Open-Meteo），把北京当前气温显示在主页卡片上。",
  "icon": "earth",
  "value": "--",
  "lines": [
    { "label": "数据源", "text": "Open-Meteo（公开接口，无需 Key）" },
    { "label": "缓存", "text": "10 分钟" }
  ],
  "dataSource": {
    "url": "https://api.open-meteo.com/v1/forecast?latitude=39.9042&longitude=116.4074&current=temperature_2m",
    "path": "current.temperature_2m",
    "refreshSeconds": 600
  },
  "link": "https://open-meteo.com/",
  "enabled": true
}
```

效果：主页上多一张卡，标题「示例天气」、右上角 `HMOL · v1.0.0`、大字是取回来的气温（取不到就显示 `--` 并附一句弱化提示），底部一行「点击打开 open-meteo.com」，**整张卡可点**。

## 五、数据源怎么写

### 取值路径 `path`

用 `.` 逐层往下走，数字段表示数组下标：

| 返回的 JSON | 想取 | `path` |
|---|---|---|
| `{"current":{"temperature_2m":23.4}}` | 23.4 | `current.temperature_2m` |
| `{"items":[{"name":"甲"},{"name":"乙"}]}` | 乙 | `items.1.name` |
| `"just a string"` | 整串 | 留空（或省略 `path`） |

能显示成一行文字的值：字符串、数字、`true`（显示「是」）、`false`（显示「否」）。取到 `null`、对象或数组会算失败并降级 —— 请用 `path` 精确取到某一层的标量。

### 缓存、超时与降级

- 取到的值缓存在**内存**里，有效期 = `refreshSeconds`（最少 60 秒）：反复进主页不会重复请求同一个接口；
- 单次请求有 **10 秒**超时；请求失败、超时、返回的不是 JSON、路径取不到值 —— 都会**降级**：卡片照常显示，主数值退回清单里的 `value`，再加一句「数据源暂时取不到（原因），当前显示的是清单中的静态内容。」；
- 关掉数据源：设置 → 扩展模块 → **数据源联网总开关**（关掉后一个请求都不发，扩展只显示静态内容）。

### 刻意不做的事

- 只发 GET，不跟随到非 http/https，不发送任何账号 / Cookie / 凭据；
- 不解析 HTML、不执行返回内容里的任何东西 —— 只当成 JSON 取值；
- 不把结果写到磁盘上（没有缓存文件、没有日志文件）。

## 六、可以用的图标

图标来自启动器内置的 lucide 图标包（`src\HMOL.App\Assets\IconPacks\lucide\`）。写错名字不会静默失效，而是**直接判清单无效**并告诉你原因。完整的可用名字清单见仓库里的 `docs/extensions.md`（清单里写 `名字` 或 `lucide/名字` 都行）。

## 七、管理界面

设置 → **扩展模块**：

| 操作 | 说明 |
|---|---|
| 新建扩展 | 先起一个文件名（= 扩展 ID），再用表单填内容 |
| 编辑 | 表单字段与上面的字段表一一对应，保存前会跑**同一套校验**并给出可读原因 |
| 启 / 停 | 只改清单里的 `enabled` 字段 |
| 删除 | 只删掉扩展目录里的那一份清单文件 |
| 重新加载 | 重新读一遍扩展目录 |
| 打开扩展目录 | 用资源管理器打开 `Data\extensions`（不存在时会创建） |
| 数据源联网总开关 | 关掉后所有扩展都不再发请求 |

列表里每一条显示：名称 / 作者 / 版本 / 有没有数据源 / 状态（已启用、已停用、加载失败 + 具体原因）。

## 八、常见问题

**Q：清单写坏了会不会把启动器弄崩？**

不会。写坏的那一个扩展会被跳过，原因显示在设置页列表里（红字），其它扩展和内置小组件完全不受影响。

**Q：能通过扩展让启动器做点别的吗（执行命令、读写文件、改设置）？**

不能，而且这是刻意的。清单里只有文字、图标名和网址三类东西，宿主没有读取「可执行内容」的代码路径 —— 能力上限就是「画一张卡」。

**Q：游戏资源（INI、地图、任务、插件）怎么装？**

按游戏资源包的形式打包，走「包管理」页导入安装 —— 那属于游戏资源，与主页扩展是两套体系，互不影响。

**Q：多个扩展的显示顺序？**

按扩展 ID（文件名）排序，与放进目录的先后无关。想调顺序就改文件名。

**Q：卡片显示「数据源暂时取不到」怎么办？**

这是降级提示，卡片仍在正常显示（内容来自清单里的静态值）。常见原因：网络不通 / 目标站被墙、接口挂了、`path` 写错、`url` 指向的接口需要鉴权。
